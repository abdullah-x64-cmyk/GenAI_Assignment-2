\begin{abstract}
This paper describes a criterion-level clinical-trial eligibility reasoning system fine-tuned on the required TrialGPT Criterion Annotations benchmark. Qwen2.5-0.5B-Instruct was adapted with LoRA using the fixed 37/8/8 patient-grouped split. On the 206-criterion held-out test split, the adapted model achieved 0.670 accuracy, 0.398 macro-F1, and 0.483 evidence micro-F1, compared with zero classification accuracy for the base model under the current structured-output parser. The adapted system averaged 0.984 s per criterion and reported no input truncation. The malformed base outputs and modest test scores expose important reliability limitations; this is a research prototype, not a clinical decision tool.
\end{abstract}
\begin{IEEEkeywords}clinical trial matching, Transformer, LoRA, eligibility classification, evidence retrieval\end{IEEEkeywords}
\section{Introduction}
Trial eligibility matching requires reasoning over each individual inclusion or exclusion criterion and grounding a decision in specific patient-note sentences. Missing evidence must remain distinct from proof of failure. The criterion-level task is not a separately labeled patient--trial outcome. This work implements a small autoregressive model that generates both the expert category and evidence sentence IDs, using only the mandated annotations.
\section{Related Work}
TrialGPT decomposes matching into trial retrieval, criterion-level reasoning, and patient-level ranking, and motivates preserving criterion granularity \cite{jiang2023trialgpt}. The Transformer uses self-attention and autoregressive decoding \cite{vaswani2017attention}. LoRA freezes pretrained weights while training low-rank updates, reducing trainable parameter count \cite{hu2021lora}. FlashAttention demonstrates exact tiled attention with reduced memory traffic, while also showing why an IO-aware GPU implementation matters \cite{dao2022flashattention}. Long-context studies find that relevant facts can be missed depending on position, so a nominal context window alone does not guarantee robust evidence use \cite{liu2023lost}. Qwen2.5 and SmolLM2 supply two small open-weight decoder candidates \cite{qwen2024,allal2025smollm}.
\section{Materials and Methods}
\subsection{Dataset and split}
The NCBI TrialGPT Criterion Annotations dataset has 1,020 rows and 53 patient IDs in the published dataset card \cite{trialgptdataset}. We sort the unique IDs and shuffle with NumPy \texttt{default\_rng(42)}, allocating 37, 8, and 8 patients to train, validation, and test. The script exports patient IDs, row counts, and leakage checks. Input fields are note, criterion type, and criterion text. Targets are expert eligibility and expert sentence IDs. All GPT-4-generated fields and correctness judgments are excluded.
\subsection{Architecture choice}
We selected Qwen2.5-0.5B-Instruct (approximately 0.49B parameters; Apache-2.0; decoder-only causal Transformer; native Qwen2 tokenizer; model card reports context up to 32,768 tokens). BF16 weights alone occupy about 0.98 GB decimal; actual training memory also includes activations, optimizer state for adapters, gradients, and cache. LoRA with short 2,048-token sequences and checkpointing is intended for a free 8--16 GB GPU. SmolLM2-360M-Instruct (0.36B, Apache-2.0, decoder-only, 8K context) is a smaller alternative, but Qwen provides more context headroom for longer notes. The downloaded base checkpoint was approximately 988 MB; training and evaluation ran on a free Colab Tesla T4 using FP16 and gradient checkpointing. Peak GPU memory was not recorded, so no measured peak-memory claim is made.
\subsection{Preprocessing and output}
The note's numbered sentences are retained. The prompt includes exactly the three required inputs. The target is JSON: \texttt{\{"eligibility":"...","evidence\_sentence\_ids\":[...]\}}. Label strings are preserved from the expert field, including insufficient-information and not-applicable categories. Evidence is represented as original note sentence IDs. The tokenizer is native to Qwen2.5. Training tokenization is limited to 2,048 total tokens, preserving the beginning of the prompt and potentially dropping later evidence. Each record logs original token count, used count, and truncation flag. Evaluation reserves up to 128 generation tokens from that budget. The observed held-out test truncation fraction was 0.000 for both base and adapted models; this does not guarantee complete evidence coverage for longer future notes.
\subsection{Fine-tuning objective and configuration}
We use causal next-token cross-entropy over target JSON tokens; prompt token labels are masked with -100. LoRA uses rank 8, alpha 16, dropout 0.05, and attention projection modules. Executed settings were AdamW, learning rate $2\times10^{-4}$, 3 epochs, microbatch 1, accumulation 8, warmup 5\%, weight decay 0.01, seed 42, and best validation-loss checkpoint. Training took 622.75 s; final logged training loss was 0.1860 and validation loss was 0.1209. The full training history is in the submission artifact archive. Greedy generation uses no sampling and a 128-token output cap for both base and adapted model.
\section{Experimental Setup and Metrics}
The scripts evaluate base and adapted checkpoints on identical validation examples and the same held-out test examples. Classification results include accuracy, macro-F1, class precision/recall/F1, and confusion matrix. Evidence is exact sentence-ID set matching with micro precision, recall, and F1. Both-empty evidence sets are treated as correct at the record level; empty/nonempty mismatches score zero. Invalid JSON is mapped to the “invalid” label and is visible in the per-example prediction log. The Colab run used a Tesla T4; training took 622.75 s (3 epochs). Test generation averaged 3.594 s/criterion for the base model and 0.984 s/criterion for LoRA. The test split contains 206 criteria from 8 patients, with no reported truncation.

\section{Limitations}
The benchmark is small and patient-grouped; performance estimates have substantial uncertainty. A generated rationale is not a verified clinical explanation; this task reports evidence IDs and should derive displayed evidence text from the source note. Small models may fail at negation, temporality, and implicit clinical reasoning. Although no truncation was observed in these runs, other longer notes may exceed the configured input budget. Base-model free-form outputs were not successfully normalized to the target schema, so the zero baseline scores should be interpreted with that limitation. The work is an educational screening prototype and must not determine clinical enrollment.
\section{Task 2: Criterion-Level Eligibility and Evidence Verification}
The evaluator preserves the expert label strings rather than mapping them into binary decisions. It returns criterion text and type, predicted category, cited sentence IDs, verbatim sentence text for IDs found in the numbered patient note, unmatched IDs, and a deterministic audit explanation. The explanation quotes only the cited text; when no sentence is cited, it explicitly states that missing evidence is not proof of either outcome. The machine-readable per-record schema is saved with the evaluation JSON. Historical Task 1 logs lacked criterion text and evidence text, so Task 2 analysis below re-aggregates their existing predictions without rerunning test inference.

\section{Conclusion}
This project provides fixed-split preparation, leakage-safe supervised fine-tuning, and matched base/adapted evaluation scripts. The held-out evaluation demonstrates a measurable improvement from LoRA adaptation but also shows that criterion reasoning and structured output remain error-prone. The artifact archive, including the adapter, is in the project results folder and is downloadable from the public GitHub repository.
\section{Task 3: Explicit KV-Cached Autoregressive Generation}
\label{sec:kv-cache}
We implemented the greedy decoding loop in \texttt{src/cache\_decode.py} rather than relying only on a high-level generation switch. The cached implementation performs one prompt prefill with \texttt{use\_cache=True}, selects the next token by argmax, and then feeds one token per forward pass while carrying the returned \texttt{past\_key\_values}. The reference implementation uses \texttt{use\_cache=False} and recomputes the entire prompt-plus-generated prefix at each step. Both implementations apply identical greedy argmax selection, EOS handling, and input IDs.

Qwen2.5 uses rotary positional embeddings. Prompt positions follow the model's zero-based positions; cached decoding explicitly assigns each new token position $L+j$, where $L$ is prompt length and $j$ is its zero-based generated-token index. The attention mask grows by one visible position per step, while the model's causal mask disallows attending to future positions. Benchmark prompts are unpadded, so no padding offset is needed. The key/value cache grows linearly with generated sequence length. Differences in floating-point kernel order can alter an argmax when top logits are nearly tied, so the benchmark records per-token agreement and exact-sequence agreement.

The reproducible comparison is implemented in \texttt{src/benchmark\_cache.py}. It verifies actual cache sequence length after prefill and every incremental update, and measures prefill latency, decode latency, tokens per second, and peak CUDA allocation for 64/256/512-token prompts and 16/32-token outputs. We measured the fine-tuned Qwen2.5-0.5B model on a Tesla T4 with float32 computation, eager attention on both paths, and four warmup tokens per path. The complete measurements are archived in \texttt{results/cache\_benchmark\_final.json}; Table~\ref{tab:cache-final} summarizes them. All six tested cached and uncached greedy sequences matched token for token. The earlier exploratory bfloat16 run with unspecified attention backend diverged on the 64- and 256-token prompts. The successful rerun changed backend and dtype together, so it establishes exact agreement under the final settings but cannot attribute the earlier mismatch to only one cause.

\section{Task 4: Tiled Attention with Online Softmax}
\label{sec:tiled-attention}
We implemented a materialized scaled dot-product attention reference and a tiled online-softmax variant in \texttt{src/online\_attention.py}. For each query tile, the tiled method visits key/value tiles and maintains a running maximum $m$, normalization sum $l$, and weighted-value accumulator $a$. For score tile $S$, it updates $m\prime=\max(m,\max(S))$, rescales the previous state by $\alpha=\exp(m-m\prime)$, then adds the shifted tile exponentials to $l$ and their product with values to $a$. The output is $a/l$. This is numerically stable because exponentials are evaluated after subtracting the current maximum. Half and bfloat16 inputs are accumulated in float32. Fully masked rows return zero.

The reference and tiled paths accept boolean visibility masks and additive score masks, including negative infinity for blocked positions. Causal masking allows each query to attend only to its current and preceding keys. For a shorter query suffix over a longer KV sequence, positions are bottom-right aligned. Tests exercise causal attention, additive and boolean masks, fully masked rows, uneven tile boundaries, and suffix queries; outputs agree with the reference and PyTorch SDPA within tight float64 tolerances. The test command and general benchmark command are documented in the README. The current local host has CPU-only PyTorch, so this run could not measure CUDA peak memory.

Table~\ref{tab:attention-cpu} reports a small CPU comparison (batch 1, two heads, head dimension 16, float32; two timed iterations after one warmup). The complete measurements are in \texttt{results/attention\_benchmark\_cpu.json}. At these short lengths, the tiled educational implementation is slower than the materialized reference and PyTorch SDPA. Its theoretical score workspace is smaller: at length 64, the reference score matrix uses 32 KiB while a 16-by-16 tile uses 2 KiB for the same batch, head count, and dtype. This compares score tensors only, not total process memory. The local measurements are noisy and do not establish GPU performance.
